本文所有数字都是在当前数据上实测得到的（统计口径见附录）。

## 0. 结论

**一句话定位**：LiDAR 负责定位，相机负责远处的识别，水面负责约束。

MariFusion 有两个核心模块和一组插件：

1. **WAHead：水线锚定检测头（Waterline-Anchored Head，新颖点，专门针对漂浮目标）**
   - **VWA（可见水线锚点）**：heatmap 的峰值和 query 的参考点放在目标**朝向传感器一侧的可见水线点**上，不放在几何中心。几何中心由（锚点、尺寸、朝向、视线方向）按几何关系解码出来。依据：LiDAR 点的质心系统性地偏向传感器一侧。boat 偏 1.9m，ship 偏 7.8m，长度超过 30m 的船 p90 偏 16m。
   - **SSR（共享海面推理）**：所有漂浮目标都浮在同一个海面上。做法是：先由各实例的水线估计**聚合出本帧海面**（3 个参数），再把海面反馈给每个实例，让它只回归相对海面的干舷残差。依据（oracle）：利用同帧共享水线后，z 误差中位数从 0.82m 降到 0.37m；只算 z 时，3D IoU 过阈值的比例从 88.7% 升到 96.0%。
   - 这相当于把 IS-Fusion 的“实例-场景协作”从**特征层面**搬到了**物理约束层面**，额外开销几乎为 0。
2. **SIF：稀疏实例级相机融合（Sparse Instance Fusion，轻量）**
   - **不做任何稠密视角变换**：没有 LSS，也没有 bev_pool。
   - 用原分辨率的地平线带图像；query 投影到左右目后做可变形采样；另有相机引导的远距离 query。
   - 相机 query 的深度来自视锥内 LiDAR 点的中值，没有点时退回到“视线与估计海面的交点”，**推理时不需要深度网络**。
   - 可靠性门控：显式的有效性掩码加光照嵌入，处理局部视场、夜间和模态缺失。
3. **插件**：Radar、Stereo、时序、9-DoF，接口统一，都不进主表。

**与主流方法的区别**：
- 市面上的方法大多沿用 BEVFusion 的“相机→BEV 稠密融合”。
- IS-Fusion 在其上加了实例级融合，但相机特征仍然只在 LiDAR 点处采样。在本数据集的远距离区段，每个目标只有约 13 个点，却有约 180px 宽的图像区域。
- 我们让 query 直接到像素里取特征，并用海面几何约束检测头，因此**更准、更轻**。

**开工前必须修的问题**（§2）：v5 pkl 的相机外参是镜像错误的；新划分还没有 pkl；z 原点和 w/l 顺序需要转换；图像未去畸变。

### 1.2 “漂浮目标”的实测证据（WAHead 的 motivation）
| 现象 | 实测 | 结论 |
|---|---|---|
| **观测平台本身在漂**：本船姿态（IMU 加速度计，相对各序列中位数的偏差） | \|roll\| p95 为 0.65–2.11°，最大 8.4°；\|pitch\| p95 为 0.87–2.84°，最大 6.4° | 与道路场景不同，**不存在固定的地面**。在 100–150m 处，1° 的倾斜对应 1.7–2.6m 的高差 |
| **目标在起伏**：同一轨迹的底面 z 抖动（片段内，≥50 帧的轨迹，共 1275 条） | std 中位 0.29m，p90 0.81m；buoy 0.59m；随距离增大（0.19m 到 0.35m） | z 不能按道路场景那样当作近似常数 |
| **同帧目标共享同一个海面**：留一法平面 oracle | 用同帧其它框拟合的平面预测某个框的底面：\|dz\| p50 从 0.82 降到 **0.37m**，p90 从 2.00 降到 1.37m；只看 z 的 3D IoU 过阈值比例从 **88.7% 升到 96.0%**（0–50m：83.4% 升到 94.7%；≥100m：84.3% 升到 93.9%） | 把“共享海面”作为场景级隐变量来推理，能把 z 误差减半 → **SSR** |
| 海面倾斜能否用 IMU 解释 | 平面斜率与 IMU 重力分量的相关系数 \|r\| ≤ 0.41，多数小于 0.1 | 不宣称 IMU 可解释；把海面当作从数据中学出的隐变量 |
| **只看得到近侧**：LiDAR 点质心相对框中心、沿视线方向的偏移 | boat −1.9m，sailboat −1.3m，ship **−7.8m**；长度超过 30m 的船中位 −7.2m、p90 −16m；归一化偏移中位 −0.34（长船 −0.44） | 大船的几何中心落在“没有点的水面”上。heatmap 的峰值应该放在有特征的可见侧 → **VWA** |
| 水面镜像鬼影点 | 框底面以下的点占比约 0%（3574 个框中只有 1% 超过 0.2） | **不是问题，论文不宣称** |
| 目标自身的 pitch/roll | ship/yacht 恒为 0；boat 的 p99 约 1°；buoy 的 p99 为 3–5° | 主表只评 yaw；pitch/roll 做成插件 |

## 2. 开工前必须修的问题（阻塞项）

1. **相机外参约定错误（致命）**。`tools/patch_maritime3d_v5_calib.py` 按“GT 中心落入图像的比例”选中了 wxyz，而这个指标对翻转不敏感。
   - **正确约定**：xyzw（ROS 顺序），表示传感器→机体；`lidar2cam = inv(T_body_cam) @ T_body_lidar`。
   - 证据：4 个序列、左右两个相机的投影叠加图，见 `figs/calib_wxyz_wrong.jpg`、`figs/calib_xyzw_correct.jpg`、`figs/calib_xyzw_seq01-03.jpg`。
   - 因此 work_dirs 中所有相机和融合结果都无效：BEVFusion 0.251（低于 TransFusion-L 的 0.434），PETR 0。
2. **新划分没有 pkl**，需要写 tables→pkl 转换器，并满足：
   - 框就在 LiDAR 系下（框内点数与 `num_lidar_pts` 逐框相等）；
   - `translation` 是几何中心，要转为底面中心 `z − h/2`；
   - `size` 的 (w,l,h) 要转为 (l,w,h)；
   - yaw 取自表内四元数（wxyz）；pitch/roll 存为独立字段。
3. **图像去畸变或双目校正**。离线做 `stereoRectify`，Stereo 插件也需要。
4. **GT-Aug 数据库**只用新的 train 重建。
5. **val 集视场内的长尾类太少**（需要你决定）：yacht 只有 2 个框，ship 79 个。可以在 `make_splits.py` 里加视场内每类框数的下限，也可以让 val 只看池化的 tail 指标。

## 3. 模型总体架构

```
 LiDAR（~40k 点, 320°）                          左 / 右目（已校正）
        │                                              │ 地平线带裁剪 2048×640（原分辨率）
 Sparse Voxel Encoder（0.1 m）                   图像骨干 + FPN（R18 / R50 / ConvNeXt）
 → BEV 400×400 @0.8 m → 2 尺度 BEV FPN                 │
        │ ◄── [插件] Radar BEV（门控相加）          2D 辅助头（投影 GT 2D 框）
        ▼                                              ▼
  F_bev ── heatmap（峰值 = 可见水线锚点, VWA）   2D 检测 → 深度 = 视锥 LiDAR 中值
        │         top-K                                   │   ／无点时：视线 ∩ 海面 π（SSR）
        ▼                                              ▼
      Q_bev ─────────────────────┬──────────────── Q_cam（远距离补召回）
                                 ▼
          ┌──────────── Decoder × L ─────────────────────────────────────┐
          │ Self-Attn（实例间）+ 海面 token π                              │
          │ BEV Deform-Attn(F_bev)                                         │
          │ SIF：Image Deform-Attn(F_img^L, F_img^R)，投影 + 有效掩码        │
          │      [插件] Radar Deform-Attn / Stereo 一致性                   │
          │      可靠性门控 g_m = σ(MLP[q, 有效率, 光照/Δt, LiDAR 密度])     │
          │ WAHead：锚点/尺寸/朝向/干舷/不确定度 → SSR 海面更新 → 几何解码   │
          └─────────────────────────────────────────────────────────────────┘
                                 ▼
        类别 + 3D 框(x,y,z,l,w,h,yaw) + IoU 质量分 + 本帧海面 π   [插件] pitch/roll
```

### 3.1 与 BEVFusion / IS-Fusion 的定位对比（论文 Related Work 和 Method 开头可直接用）
| 维度 | BEVFusion（ICRA'23） | IS-Fusion（CVPR'24） | **MariFusion** |
|---|---|---|---|
| 相机→3D | LSS 稠密深度分布 → BEV | Point-to-Grid：图像特征**只在 LiDAR 点处**采样，再汇聚到 BEV | **不做视角变换**：query 投影到图像，稀疏采样 |
| 远距离（13 点 vs 180px） | 深度离散化导致特征沿射线模糊 | 每个目标只有约 13 个采样位置 | 采样点覆盖整个投影框，远处目标的像素都用上 |
| 实例-场景协作 | 无 | 特征级：Instance-to-Scene，W·H·K 规模的交叉注意力 | **几何级**：共享海面（3 个参数），加上 decoder 内的实例间注意力 |
| 检测头 | TransFusion（中心 heatmap） | TransFusion（中心 heatmap） | **WAHead**：可见水线锚点 + 共享海面 + 几何解码 |
| 局部视场 / 夜间 / 模态缺失 | 无显式处理 | 无显式处理 | 有效性掩码 + 可靠性门控 + 模态 dropout |
| 推理开销 | nuScenes 上 4.2 FPS（IS-Fusion 论文 Tab.2 的测量） | nuScenes 上 3.2 FPS（同表） | 目标：明显更轻（§5，需实测对比） |

**借鉴了 IS-Fusion 的两点**：
- 实例级多模态上下文聚合，包括 top-K 实例和实例间自注意力；
- “实例与场景相互增强”的思想，但我们让协作通过**物理约束（海面）**来实现，不用稠密的交叉注意力。

**有意没有照搬的两点**：
- Point-to-Grid 在远距离稀疏点的场景下信息不足；
- Instance-to-Scene 在 400² 的 BEV 上开销大（每层 16 万个格子 × 200 个实例）。

### 3.2 LiDAR 分支（BEV 中枢）
- 体素 [0.1, 0.1, 0.2]m，范围 [-160,-160,-8, 160,160,24]（与 MaritimeMetric 一致）。
- SparseEncoder 下采样 8 倍，得到 400² 的 BEV（0.8m），再用 0.8m 和 1.6m 两个尺度的 BEV FPN。1.6m 那一层用来给 70–90m 的大船提供感受野。
- 额外输出 LiDAR 密度通道 log(1+每格点数)，供门控使用。

### 3.3 WAHead：水线锚定检测头（核心贡献 ①）

**记号**：GT 框 b = (c, l, w, h, ψ)。视线方位角 θ = atan2(c_y, c_x)，单位视线向量 r̂ = (cosθ, sinθ)。框沿视线方向的半长为：

```
e(l, w, ψ, θ) = (l/2)·|cos(ψ−θ)| + (w/2)·|sin(ψ−θ)|
```

**(a) VWA：可见水线锚点**
- 锚点：a = c_xy − κ·e·r̂，即从中心朝传感器方向退 κ 倍半长，落在可见侧。κ ∈ [0,1]，κ=0 时退化为 CenterPoint/TransFusion 的中心。主设置取 κ=0.5，与实测的归一化偏移 −0.34 到 −0.44 对应；做 κ ∈ {0, 0.5, 1} 的消融。
- heatmap 的 Gaussian 放在 a 上，半径随尺寸自适应并设上限。top-K 的 query 以 a 为参考点，这里正好有 LiDAR 特征。
- 回归量：Δa、log(l,w,h)、sin/cos ψ、干舷 f、不确定度 (σ_z, σ_r)，以及 IoU 质量分。
- **几何解码**：用 θ̂ = atan2(â_y, â_x) 算出 ĉ_xy = â + κ·e(l̂, ŵ, ψ̂, θ̂)·r̂(θ̂)。
- 损失加在解码后的框上（L1 + 3D GIoU），并对 Δa 加 L1。尺寸和朝向的梯度会经过解码流到中心，所以大船的尺寸误差和中心误差是几何一致的，不再是各自独立的回归。

**(b) SSR：共享海面推理（instance → scene → instance）**
- 每个 query i 给出自己的水线点 (â_i, ẑ_bot,i) 和权重 ω_i = score_i / σ_z,i²。
- 用可微的加权最小二乘加先验，求出本帧海面 π：z = αx + βy + γ：

```
[α,β,γ] = (XᵀΩX + λI)⁻¹ (XᵀΩz + λ·π₀)
```
  - 其中 π₀ 由全局池化的 BEV 特征经小 MLP 预测。
  - 帧内目标少于 3 个或几何退化时，自动退回 π₀；空帧占 57%，这种情况很常见。
- **scene → instance**：最终底面高度 ẑ_bot,i = π(â_i) + f_i。f_i 是按类别条件化的干舷残差，方差很小。π 被编码成一个“海面 token”，送进下一层 decoder 的自注意力，逐层迭代。
- **监督信号不需要额外标注**：在 GT 框数 ≥3 且空间跨度足够的帧上，对 GT 底面做鲁棒平面拟合，得到 π_GT；平面损失用 L1(π, π_GT)。
- 不确定度用 Laplace NLL：|Δ|/σ + log σ。它同时作为 SSR 的权重，并参与最终得分（cls^α·IoU^β），用来刻画“漂浮不定”带来的回归难度。
- 顺带的好处：π 在图像中的投影就是地平线（海面的消失线），可以给 Q_cam 提供“视线 ∩ 海面”的深度兜底（§3.4）。

**这个检测头的卖点**：
- 物理先验明确：目标浮在同一个会动的海面上，而且只能看到近侧。
- 每个子模块都有数据 oracle 支撑（§1.2）。
- 额外计算只有 3 个平面参数和一次解码。
- 和融合方式正交，可以直接插到 TransFusion、BEVFusion、IS-Fusion 的检测头上。这可以作为一个额外实验：给主流 baseline 换上 WAHead，展示通用性。

### 3.4 SIF：稀疏实例级相机融合（核心贡献 ②，轻量）
- **图像输入**：左右目各做 2048×640 的地平线带裁剪，不缩放（像素比全图少 41%）。
- **2D 辅助头**：CenterNet 风格，监督信号是投影出的 GT 2D 框。它让图像特征学会水面目标的外观，并在推理时给 Q_cam 提供提议。
- **Q_cam**：左右目各取 top-60 个 2D 检测。深度用 2D 框中心 50% 区域内 LiDAR 点的中值；少于 3 个点时，用框底边中点的视线与海面 π 的交点。这里没有深度网络，推理开销约等于 0。
- **Image Deform-Attn**：把 query 的 3D 框关键点（中心、4 个 BEV 角点取半高、顶点）投影到左右目，在 1/8 和 1/16 两个尺度上做可变形采样，并记录有效掩码（在图内且深度大于 0）。
- **可靠性门控**：

```
g_m = σ(MLP([q ; 有效采样比例 v_m ; 质量嵌入 s_m ; LiDAR 密度 ρ])) · 1[v_m > 0]
q  ← q + f_bev + Σ_m g_m ⊙ W_m f_m
```
  - 相机的 s_m 来自图像带亮度统计（均值和分位数）经过 MLP，不需要昼夜标签；雷达的 s_m 是扫描时间差 Δt。
  - 视场外 g=0，模型自动退化成 LiDAR-only，即“不劣于 LiDAR”的保证。
- **模态 dropout**：整组相机 0.25，单个相机 0.1，雷达 0.3。

### 3.5 插件（统一接口：特征源 + 可选 query 生成器 + 门控）
| 插件 | 做法 | 预期与叙事 |
|---|---|---|
| **Radar** | 用 LiDAR 岸线配准出 m/px 和外参；用 `timestamp_deg.txt` 生成逐格的扫描时间差 Δt 通道；小型 BEV CNN 编码后门控相加进 F_bev，并在 decoder 中做雷达的可变形注意力；seq00 的掩码为 0 | 看夜间、>100m 和视场外。如果增益有限，就如实写成一个发现：0.8Hz 的扫掠雷达对 10Hz 检测的边际价值有限 |
| **Stereo** | 对视场内的 query 取 D 个深度假设（间隔 ∝ d²/(fB)），用左右特征的分组相关精修深度 | 116m 处视差约 13px，0.5px 误差对应约 4.4m 深度误差。主要帮助 LiDAR 少于 5 点的目标和纯相机赛道 |
| **时序** | 先补 ego pose（Pohang 的 GPS/AHRS 或 LiDAR 里程计），再做 query 传播；SSR 的海面也可以跨帧平滑 | journal 扩展，同时解决 velocity 全为 0 的问题 |
| **9-DoF** | 加 sin(pitch) 和 sin(roll) 两个输出，损失权重 0.2 | 数据中近乎退化，只在 buoy 上报测地线误差 |

## 4. 训练配方
- **Stage 1（LiDAR-only + WAHead）**：24 epoch，使用 GT-paste（只用 train 的 dbinfos，粘贴时让底面贴合该帧的 π_GT），最后 4 个 epoch 关闭。
- **Stage 0（2D 预热，与 Stage 1 并行）**：图像骨干加 2D 头，训练 12 epoch。
- **Stage 2（融合）**：12 epoch，不用 GT-paste；图像骨干的学习率乘 0.1。
- **采样**：帧级 RFS，让 ship、yacht、buoy 所在帧重复约 3–5 倍并设上限；不用 CBGS。空帧每个 epoch 保留 1/3。
- **增强**：LiDAR 做全局旋转和缩放，同步更新 lidar2cam；融合阶段不做 y 翻转；图像做颜色抖动和带状裁剪抖动（±32px）。另外加**海面扰动增强**：对整帧施加 ±1° 的随机横摇和俯仰，以及 ±0.3m 的升沉，同时变换 GT 和 π_GT，这正好对应“平台在漂”这一现象。
- **优化**：AdamW，Stage 1 学习率 2e-4、Stage 2 学习率 1e-4，cosine 调度，8×A800，每卡 batch 4。
- **损失**：L = L_det（focal + L1 + GIoU + IoU 质量 + Laplace NLL）+ 0.5·L_plane + 0.5·L_2d。

## 5. 轻量化设计与测量协议

**设计原则**（每条都能量化）：
| 原则 | 我们的做法 | 对比项的规模（按本数据配置计算） |
|---|---|---|
| 不做稠密相机视角变换 | 只在 K≈260 个 query 处采样图像特征 | LSS：2 相机 × 80×256 × 118 个深度 bin ≈ **483 万**个视锥点 → bev_pool |
| 实例-场景协作不用稠密注意力 | 共享海面只有 3 个参数，开销 O(K) | IS-Fusion 的 I2S：400² 个格子 × 200 个实例 ≈ **3200 万**个注意力对/层 |

| 检测头几乎零额外开销 | WAHead 只增加 3 个平面参数和一次几何解码 | — |

## 6. 评测协议
沿用并扩展 `MaritimeMetric`：IoU-AP40，boat/ship/sailboat/yacht 的阈值为 0.5、buoy 为 0.25，范围 ≤160m。
1. **区域**：360°（主表）；相机视场内（按标定投影判断，替换现有的方位角近似）；视场外（检验是否不低于 LiDAR-only）。
2. **分层**：距离 0–50 / 50–100 / 100–160m；难度 L1（≥20 点）和 L2（全部）；昼（seq00、02、03）和夜（seq01）；head（boat）和 tail（其余池化）；**船长 <15 / 15–30 / >30m**，用来检验 VWA。
3. **WAHead 专用指标**：z 误差（ATE-z）；3D AP 与 BEV AP 之差，这个差值反映 z 的质量，是 SSR 的直接证据；平面误差 |π − π_GT|。
4. **鲁棒性**：相机全关、单目失效、LiDAR 线数降到 32、雷达开关；**平台扰动测试**：对测试帧施加横摇/俯仰/升沉扰动。
5. **补充指标**：LET-3D-AP（用于纯相机和双目赛道）；mAOE（排除 buoy）和 AOE180。
6. **统计**：片段级 bootstrap 95% 置信区间；tail 类只报池化指标或带 CI 的结果。

## 9. 论文叙事（benchmark 论文中的方法部分）
- **Observation**（放在数据集章节中，用 §1.2 的数字）：水面上没有固定的地面，平台和目标都在漂；远处目标“点少像素多”；大船只看得到近侧。
- **Method**：
  - WAHead：一个物理先验明确、几乎零开销、可以插到任何检测头上的模块；
  - SIF：轻量、面向远距离的稀疏实例级融合。
- **Evidence**：
  - oracle 实验：共享海面让 z 误差减半；
  - A1–A3 的消融，加上给主流方法换 WAHead 的通用性实验；
  - 精度-延迟 Pareto 图，与 BEVFusion 和 IS-Fusion 对比；
  - 鲁棒性：夜间、相机失效、平台扰动。

## 11. 风险与备选
- **SSR 的实际收益低于 oracle**：oracle 用的是 GT 框拟合的平面。模型从预测框估计平面会更吵，但有不确定度加权和 π₀ 先验兜底。如果收益小，可以退一步，只保留“平面 token 作为 decoder 上下文”这一部分。
- **VWA 对小目标没有收益**：这是预期的，κ 的效应应该集中在长船上。消融要按船长分组展示。
- **长尾统计力不足**（test 中 ship 只有 3 个实例）：用池化指标加 CI。
- **残余标定误差**（约 10–20px）：可变形采样有一定容忍度，另外加外参扰动增强。
- **轻量化的结论必须实测**：§5 的规模数字只是量级论证。
- **相关工作**：据我所知，2024 年已有基于 Pohang Canal 的标注工作（PoLaRIS），请核实并在论文中明确差异。

## 附录：统计口径
- 数据源：`splits/tables/detection/v1.0-*` 的 JSON 表，以及 `dataset/<seq>/calibration`（xyzw，传感器→机体）。
- 视场内：GT 中心投影到任一原始图像内，且深度大于 0.5m。2D 宽度和行分布：8 个角点投影后的包围框。
- IMU 姿态：`<seq>/lidar_front/imu.txt` 的加速度计做 ±0.25s 滑动平均后得到重力方向，再减去各序列的中位数。
- 留一法平面 oracle：取 train 中框数 ≥5、x 和 y 跨度都大于 40m 的帧；对每个框，用同帧其它框的底面中心做最小二乘平面，预测该框的底面。对照组是按类别的全局中位底面高度。只看 z 的 3D IoU = (h−|dz|)/(h+|dz|)。
- 可见侧偏移：随机 300–500 帧，框内点数 ≥10 的框；框内点质心相对框中心、沿视线方向的投影，归一化时除以 e(l,w,ψ,θ)。
