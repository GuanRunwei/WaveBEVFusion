# MariFusion：面向航运场景的相机 + LiDAR 3D 检测 benchmark 模型

版本：2026-09-25 · 模态：双目相机 + LiDAR（Radar 等为可选插件，不进入本文主线）
配套文件：数据证据和完整规划见 [BENCHMARK_MODEL_DESIGN.md](BENCHMARK_MODEL_DESIGN.md)。

---

## 1. 核心思路

MariFusion 针对航运场景的三个事实，各给出一个对应设计：

| 场景事实（实测） | 对应设计 |
|---|---|
| **远处点少、像素多**：相机视场内目标的中位距离为 102–119m；在 100–150m 处，一个目标只有约 13 个 LiDAR 点，在图像中却有约 180px 宽 | **SIF 稀疏实例级融合**：不把图像抬升到 BEV，而是让每个 3D query 投影到原分辨率图像上直接取像素特征 |
| **目标浮在会动的水面上**：同帧所有目标共享同一个海面；LiDAR 只能看到目标朝向传感器的一侧 | **WAHead 水线锚定检测头**：用可见水线锚点定位，用共享海面约束高度 |
| **相机只覆盖约 24% 的目标，夜间帧占 33%** | **可靠性门控**：显式的有效性掩码，加上模态 dropout |

定位分工可以概括为：LiDAR 负责定位，相机负责远处的识别，水面负责约束。

## 2. 总体结构

```
 LiDAR 点云（~1.7 万点/帧, 320°）              左 / 右目图像（2048×1080）
          │                                            │ 地平线带裁剪 → 2048×640（原分辨率）
  稀疏体素编码（0.1 m）                          图像骨干 + FPN（1/8, 1/16）
  → BEV 400×400 @0.8 m（±160 m）                       │
  → 两尺度 BEV FPN（0.8 / 1.6 m）                  2D 辅助检测头
          │                                            │
  锚点 heatmap（峰值 = 可见水线锚点）              2D 框 → 3D 参考点
          │ top-K                                      │ 深度 = 视锥内 LiDAR 中值 / 视线∩海面
          ▼                                            ▼
        Q_bev ───────────────────┬─────────────────── Q_cam
                                 ▼
           ┌──────────── SIF 解码层 × L ─────────────────────────┐
           │ ① 实例间自注意力（附带海面 token）                     │
           │ ② BEV 可变形注意力                                     │
           │ ③ 图像可变形注意力（左/右目，投影 + 有效掩码）          │
           │ ④ 可靠性门控融合                                       │
           │ ⑤ WAHead：锚点/尺寸/朝向/干舷 → 海面更新 → 几何解码     │
           └─────────────────────────────────────────────────────┘
                                 ▼
          3D 框 (x, y, z, l, w, h, yaw) + 类别 + IoU 质量分 + 本帧海面 π
```

与 BEVFusion 系方法的根本区别：**整个模型没有“图像 → BEV”的稠密视角变换**。相机信息只在 query 处按需读取。

## 3. 模块详解

### 3.1 LiDAR BEV 中枢
- 范围 ±160m，z 为 [-8, 24]m；体素 0.1 × 0.1 × 0.4m，稀疏编码后下采样 8 倍，得到 400² 的 BEV（每格 0.8m），2.5m 的浮标约占 3 格。
- SECOND + FPN 输出 0.8m 和 1.6m 两个尺度。1.6m 那一层为 70–90m 的大船提供足够的感受野。
- 另外输出一个 LiDAR 密度图 log(1+每格点数)，给门控使用。
- 工程注意：3200×3200×80 的网格在每卡 batch 4 时，会超出 mmcv 稀疏卷积的 int32 索引上限，所以每卡 batch 取 2。

### 3.2 相机编码
- **地平线带裁剪**：左右目各裁 2048×640（约第 256–896 行），不缩放。88% 的视场内目标完整落在这个带内，比全图少 41% 像素。
- **骨干**：R50（Base 档）；Lite 档用 R18 加 0.5 倍输入；Large 档用 ConvNeXt-B。
- **2D 辅助头**（CenterNet 风格）：监督信号是 3D GT 投影出的 2D 框。训练时它让图像特征学会水面目标的外观；推理时它为 Q_cam 提供提议。

### 3.3 双来源 Query
- **Q_bev**：在 BEV 的锚点 heatmap 上取 top-K（K=200）。
- **Q_cam**：只用于远距离、LiDAR 稀疏的目标，每个相机取 top-60 个 2D 检测。
  - 深度优先取 2D 框中心 50% 区域内 LiDAR 投影点的中值；
  - 少于 3 个点时，取框底边中点的视线与海面 π 的交点。
  - 这个过程不需要深度网络。
- 两类 query 合并后加上来源嵌入，由 Hungarian 一对一匹配自然去重，不需要 NMS。

### 3.4 SIF：稀疏实例级融合（贡献 ②，轻量）
每个解码层中，query q 的 3D 参考框取 7 个关键点：中心、4 个 BEV 角点（取半高处）、顶点和底点。把它们投影到左右目，在 1/8 和 1/16 两个尺度上做可变形采样：

```
f_img^v = DeformAttn(F_img^v, Proj_v(关键点))        v ∈ {左, 右}
有效掩码 m^v：投影点在图像内且深度 > 0
g^v = σ(MLP([q ; 有效比例(m^v) ; 光照嵌入 s^v ; LiDAR 密度 ρ])) · 1[有效比例 > 0]
q  ← q + DeformAttn(F_bev, 参考点) + Σ_v g^v ⊙ W f_img^v
```

- **光照嵌入 s^v**：由图像带的亮度统计（均值和分位数）经 MLP 得到，不需要昼夜标签。
- **视场外 g=0**：模型自动退化成 LiDAR-only，从结构上保证不劣于 LiDAR。
- **模态 dropout**：训练时整组相机的丢弃概率为 0.25，单个相机为 0.1。同一个模型因此可以直接做相机失效评测。
- **与 IS-Fusion 的区别**：IS-Fusion 的 Point-to-Grid 只在 LiDAR 点处取图像特征，远处每个目标只有约 13 个采样点。SIF 的采样点覆盖整个投影框，远处目标的像素都被用上。

### 3.5 WAHead：水线锚定检测头（贡献 ①，针对漂浮目标）

**记号**：框中心 c，视线方位 θ = atan2(c_y, c_x)，单位视线向量 r̂(θ)。框沿视线方向的半长为：

```
e(l, w, ψ, θ) = (l/2)·|cos(ψ − θ)| + (w/2)·|sin(ψ − θ)|
```

**(a) VWA：可见水线锚点**
- 锚点定义为 a = c − κ·e·r̂，即从中心朝传感器方向退 κ 倍半长，落在 LiDAR 看得见的那一侧。κ=0 时退化为常规的中心 heatmap；主设置取 κ=0.5。
- heatmap 的 Gaussian 放在 a 上，query 的初始位置也是 a，这里有 LiDAR 特征。
- 网络回归锚点 â，中心再按几何关系解码：ĉ = â + κ·e(l̂, ŵ, ψ̂, θ̂)·r̂(θ̂)。沿视线平移不改变方位角，所以 θ̂ = atan2(â) 是精确的。
- 除了各回归量各自的 L1 损失，还对解码后的中心加一项 L1。这样尺寸和朝向的误差会通过几何关系传到中心，大船的中心和尺寸在几何上保持一致。
- **数据依据**：LiDAR 点质心沿视线偏向传感器一侧，boat 约 1.9m，ship 约 7.8m，长度超过 30m 的船 p90 达 16m。归一化偏移为 −0.34 到 −0.44。

**(b) SSR：共享海面推理**
1. **instance → scene**：每个 query 给出自己的水线点 (x̂_i, ŷ_i, b̂_i)，权重 ω_i = score_i²。
2. 用可微的加权最小二乘加先验，求出本帧海面：

```
π = argmin Σ ω_i (a·x_i + b·y_i + c − b̂_i)² + λ‖π − π₀‖²
```
   其中 π₀ 由全局池化的 BEV 特征经 MLP 预测。空帧或只有 1–2 个目标时，结果自动退回 π₀。
3. **scene → instance**：最终底面高度 ẑ_bot,i = π(x̂_i, ŷ_i) + f_i，f_i 是干舷残差。π 同时编码成一个海面 token，送进下一层 decoder 的自注意力。
4. **监督信号不需要额外标注**：
   - 最终高度用 L1；
   - 每个 query 自己的水线估计 b̂_i 用辅助 L1；
   - 海面本身用 L1(π, π_GT)，其中 π_GT 在 loss 中由增强后的 GT 框底面做鲁棒拟合得到（要求至少 3 个框且不共线）。
5. **数据依据（oracle）**：
   - 利用同帧的共享海面后，z 误差中位数从 0.82m 降到 0.37m，p90 从 2.00m 降到 1.37m；只看 z 时，3D IoU 过阈值的比例从 88.7% 升到 96.0%。
   - 同一目标的底面 z 在片段内抖动：中位 0.29m，浮标 0.59m。
   - 海面倾斜与 IMU 姿态的相关性弱，所以海面作为隐变量学习，不依赖 IMU。

**开销**：每帧只多 3 个平面参数，加上一次几何解码，几乎可以忽略。WAHead 与融合方式无关，可以直接替换 TransFusion、BEVFusion、IS-Fusion 的检测头，据此做通用性实验。

## 4. 训练

| 阶段 | 内容 | 设置 |
|---|---|---|
| S0：2D 预热 | 图像骨干 + 2D 辅助头，在投影出的 2D 框上训练 | 12 epoch，可以和 S1 并行 |
| S1：LiDAR + WAHead | BEV 中枢、Q_bev 和 WAHead | 20 epoch，BEVFusion 的周期调度，8 卡 × 每卡 2 帧 |
| S2：融合 | 加入 SIF、Q_cam 和门控；加载 S0 和 S1 的权重 | 约 10 epoch；图像骨干学习率乘 0.1；不用 GT-paste |

- **采样**：保留全部有标注帧，空帧只保留三分之一（训练集 57% 是空帧）；尾部类别用帧级 RFS，不用 CBGS（ship 在训练集里只有 5 个实例）。
- **增强**：
  - LiDAR 做全局旋转、缩放和平移，同步更新 lidar2cam；
  - 海面扰动：±1° 的横摇和俯仰、±0.3m 的升沉，对应“平台在漂”；
  - 图像做颜色抖动，地平线带在竖直方向随机偏移 ±32px。
- **损失**：L = focal(cls) + L1(框编码) + L1(解码后的中心) + L1(海面) + GIoU + IoU 质量分 + 0.5·L_2d。

## 5. 轻量化

| 设计 | MariFusion | 对照项（按本数据配置计算） |
|---|---|---|
| 相机 → 3D | 只在约 260 个 query × 7 个关键点处采样 | LSS：2 相机 × 80×256 × 118 个深度 bin ≈ 483 万个视锥点 |
| 实例-场景协作 | 共享海面只有 3 个参数，开销 O(K) | IS-Fusion 的 Instance-to-Scene：400² 个格子 × 200 个实例 ≈ 3200 万个注意力对/层 |
| 图像输入 | 2048×640 的地平线带 | 全图 2048×1080 |
| 深度 | 视锥内 LiDAR 中值，兜底用海面交点 | 深度分布网络 |

**档位**：
- Lite：R18、0.5 倍图像带、单尺度 BEV、3 层 decoder。
- Base：R50、原分辨率图像带、两尺度 BEV、6 层 decoder。
- Large：ConvNeXt-B。

**测量协议**：统一报告参数量、FLOPs、A800 上 FP16、batch=1 的延迟，以及显存峰值；与 BEVFusion、IS-Fusion 在相同输入下对比，画精度-延迟的 Pareto 图。上面的规模数字只是量级论证，结论以实测为准。

## 6. 评测与关键消融（C+L 部分）

**评测**：IoU-AP40（boat、sailboat、ship、yacht 的阈值为 0.5，buoy 为 0.25），范围 ≤160m。分以下维度报告：
- 区域：360° / 相机视场内 / 视场外；
- 距离：0–50 / 50–100 / 100–160m；
- 昼夜；
- 船长：<15 / 15–30 / >30m；
- 类别：head / tail；
- 额外指标：ATE-z，以及 3D AP 与 BEV AP 之差（用来反映海面约束的效果）。

| 消融 | 预期现象 |
|---|---|
| κ = 0 / 0.5 / 1（VWA） | 长度 >30m 的船、>100m 的 BEV AP 提升；小目标持平 |
| SSR：无 / 有 / oracle 海面 | 3D AP 与 BEV AP 之差缩小，ATE-z 下降 |
| 在 TransFusion-L、BEVFusion、IS-Fusion 上各自换成 WAHead | 各方法都有提升，证明通用性 |
| 相机融合方式：LSS-BEV / Point-to-Grid / SIF | SIF 在视场内、100–160m 的效果最好，且最快 |
| 图像输入：0.5 倍全图 vs 原分辨率地平线带 | 浮标和 >100m 的目标提升 |
| Q_cam 开关 | 视场内的召回率提升 |
| 门控：拼接 / 门控 / 门控+掩码+dropout | 夜间、相机失效时不跌破 LiDAR-only |
| Lite / Base / Large | 画 Pareto 曲线 |

## 7. 与主流方法的定位

| | BEVFusion（ICRA'23） | IS-Fusion（CVPR'24） | **MariFusion** |
|---|---|---|---|
| 相机 → 3D | LSS 稠密深度 → BEV | 图像特征只在 LiDAR 点处采样 → BEV | 不做视角变换，query 投影后稀疏采样 |
| 实例-场景协作 | 无 | 特征级的稠密交叉注意力 | 几何级的共享海面 + 实例间注意力 |
| 检测头 | 中心 heatmap | 中心 heatmap | 可见水线锚点 + 海面约束 + 几何解码 |
| 局部视场 / 夜间 | 无显式处理 | 无显式处理 | 有效性掩码 + 门控 + 模态 dropout |
| 速度 | nuScenes 上 4.2 FPS | nuScenes 上 3.2 FPS | 目标是明显更轻（待实测） |

**借鉴 IS-Fusion 的地方**：top-K 实例、实例间自注意力、实例与场景相互增强。
**不照搬的地方**：Point-to-Grid 在远距离稀疏点的场景下信息不足；Instance-to-Scene 在 400² 的 BEV 上开销过大。
